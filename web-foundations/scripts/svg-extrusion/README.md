# Deterministic SVG extrusion compiler

`cli.mjs` converts the supported SVG subset into a manifest, indexed geometry provider, Rive scene-contract fragment, and canonical fallback.

```sh
node scripts/svg-extrusion/cli.mjs --input docs/assets/icons/fava-mark-static.svg --output build/favicon-3d --config scripts/svg-extrusion/fixtures/config.json
```

V1 accepts one closed filled contour per `path`, absolute or relative `M/L/C/Z`, implicit repeated coordinate groups, decimal signs and exponents, opaque solid fills, `nonzero`/`evenodd`, and path-local affine `matrix`, `translate`, `scale`, or `rotate` transforms in written order. A `Z`/`z` closepath terminates the contour; any later drawing command, including SVG's implicit post-close subpath, rejects. Transform lists use a strict tokenizer: named functions only, exact numeric arity, no empty arguments, and legal whitespace/comma separators. Paint follows `solid-hex-or-rgb/v1`: opaque CSS hex with 3 or 6 digits, or comma-form `rgb()` with 0–255 channels. Inline `style` may resolve only `fill`, `fill-rule`, and `stroke:none`; path/root classes, opacity properties, alpha-bearing fills, variables, inherited colours, paint functions, and unknown presentation attributes reject. Affine transforms are baked into cubic control points before adaptive flattening, so anisotropic or magnifying transforms cannot enlarge error beyond the declared screen-space tolerance. SVG coordinates are then Y-inverted and mapped into a centered right-handed model whose X/Y units equal one `viewBox` maximum dimension. Front faces are CCW at Z=0; backs extend toward negative Z. Matrices use column vectors.

V1 rejects XML entities/DOCTYPE, groups with transforms, multiple subpaths/holes, strokes, text/images, masks, clips, filters, gradients/patterns, unsupported path commands, degenerate or self-intersecting contours. `manifest.json` is `svg-to-rive-3d/v1`; `geometry.json` is `rive-animascript-3d/generated-provider/v1` with triangle-list positions, unit normals, indices, and per-facet spans. Facet count is always parsed data; only the favicon golden test asserts 13.

The bounded XML lexer consumes every start-tag character. Every attribute must have a unique XML name, `=`, and a single- or double-quoted value; unquoted, duplicate, unterminated, namespaced path, boolean, and residual-token syntax rejects before semantic allowlists run. Namespace declarations are permitted only on the SVG root through the explicit root allowlist; `xmlns`/`xmlns:xlink` must be the SVG/XLink namespaces when present, and `width`/`height` are optional positive unitless-or-`px` lengths rather than geometry inputs.

The V1 document grammar is exactly one non-self-closing `<svg ...>` root, one or more direct canonical self-closing `<path .../>` children, and the exact `</svg>` end tag. Tag scanning is quote-aware; comments are ignored only outside tags. Nested/multiple SVG roots, containers, explicit path end tags, `/ >`, `//>`, `/ />`, closing-tag residue, markup inside attribute values, text, and any other child context reject rather than introducing an unbaked viewport, coordinate, or style system.

Whitespace is XML `S` only (space, tab, CR, LF) in every tokenized position — tag boundaries, attributes, `d`, `transform`, `viewBox`, style declarations, and root lengths. JavaScript `\s`/Unicode whitespace such as NBSP, U+2028, U+FEFF, or form feed rejects instead of being normalized into separators. Path coordinates and every derived value (normalized ring, signed area, centroid, depth, emitted position/normal buffers) must be finite; non-finite or overflowing input rejects rather than serializing `null`. `viewBox` accepts only SVG-number tokens with single comma-wsp boundaries — no `Number()` coercion (`0x`, `0b`, `0o`) or collapsed comma runs — and path commas may appear only between two numbers. XML comments must be well-formed, and attribute values and comment bodies may contain only XML characters. An optional `<?xml …?>` declaration is honored only at offset 0 and must match the strict `XMLDecl` production; whitespace or comments before it reject, as do prototype-chain attribute names such as `__proto__`.

## X2 runtime pipeline

`pack-rive-mesh.mjs` consumes a generated `geometry.json` + `manifest.json` pair and emits the Rive project's blob assets (`favicon-vertices.bin`, `favicon-indices.bin`) plus `favicon_mesh.as`, a generated constants module with vertex/index/facet counts and model bounds. Vertex records are 40-byte interleaved `f32` values: position xyz, unit normal xyz, source fill rgb, and the facet's source-order index — the identity shared by the shader, the CPU picker, and the selection bitset. The packer validates schema versions, contiguous facet spans, index ranges, and the uint16 index limit; outputs are deterministic.

`verify-fidelity.mjs` is the independent X2 acceptance verifier. It rebuilds the camera model (world → view → clip → depth) in plain JavaScript, rasterizes the generated triangles in software, and compares Rive GPU captures (`build/canonical-*.png`, `build/gpu-manifest.json`) against the provider for acceptance items A1–A8. `capture-x2-evidence.mjs` replays each item, stores immutable command transcripts under the phase pack's `baseline/X2/`, and writes `PHASE-X2-EVIDENCE.json`.

## X3 interaction pipeline

`choreo.as` owns the 9 s elapsed-time loop: staggered per-facet extrusion/retraction, a separation pulse, quaternion-slerp inspect camera weighting, and exponential frame-rate-independent orbit damping. `pick.as` is a pure CPU picker over the packed blobs — it rebuilds the camera ray from the shared frame, applies the same animated transforms the shader uses, mirrors the GPU discard rule and `lessEqual` later-source-order tie-break, and returns the nearest positive visible facet or -1. `main.as` wires pointer down/move/up (3 px drag deadzone), click/tap toggling into a 256-bit selection word set in the frame uniform, touch, and reset; every pick logs a parseable `x3pick facet=N selected=S count=C` (or `x3pick reset`) line.

`verify-picking.mjs` is the independent X3 acceptance verifier: it re-implements the choreography math and picker in plain JavaScript, plans expected-ID fixtures from the generated provider (small/overlapping/large facets, occlusion, separated motion, selected Z offset, front/back culling, narrow/wide, touch), drives `rive --commands` pointer sessions, and compares logged picks against its own predictions for A1–A11. `capture-x3-evidence.mjs` replays each item into `baseline/X3/` transcripts and writes `PHASE-X3-EVIDENCE.json`. `tests/interaction-test.as` covers the choreography/quaternion/damping contracts and picker fixtures at edit time via `rive --test`.
