# Phase X0 — Evidence and readiness

## Goal

Complete source discovery, verify corpus coverage and freeze the teaching assumptions before product work.

## Entry gate

User request and studio/project contracts read. Initial work is recorded in SESSION-RECEIPT.md; do not restart completed extraction.

## Deliverables

Citation/source ledger; source hashes and vector counts; cohort readiness checklist; placement/hour decision; refined architecture.

## Scope

Read books and existing lessons; complete authorized indexing and verification. Do not rewrite shared pipelines, invent source metadata or publish lessons.

## Implementation prompt

Template — execute only after the entry gate passes.

```text
Read INDEX, TECHNICAL-DIRECTOR-CASCADE, SOURCES and this runbook.
Read SESSION-RECEIPT and inspect any active ingestion first. Verify all five technical vaults are indexed with measurable vector coverage. Run scoped Rust/Wasm and audio searches, open full candidate nodes and resolve citations. Resolve or explicitly quarantine bibliographic gaps. Confirm cohort size, prior Rust/JS/3D knowledge, target devices, homework allowance and exact location in the course. Record assumptions as provisional if answers are unavailable. Adopt six short lessons only with a feasible rehearsal plan.
Run the Acceptance checks below and record actual commands and exits.
Do not mark DONE; hand off the packet for fresh local Qwen cold review.
Use the orchestrator's closing protocol and amend-on-surprise rule.
```

## Acceptance

- [ ] Every supplied EPUB has a SHA-256, readable extraction, nonzero node count and documented extraction warnings.
- [ ] Read-only Postgres counts distinguish nodes from vectors for each source; semantic retrieval returns relevant non-heading content from both Rust and audio sources.
- [ ] Every published-intent scholarly claim has an actual source node, full context, resolver result and verified printed folio/section; unresolved claims stay private or are omitted.
- [ ] Timetable sums to 720 minutes; assess required prior knowledge and explicitly account for breaks/homework and official course placement.
- [ ] Run a short readiness task: change a JS event handler, transform an array, use Git to record the change and manipulate a mesh/camera in the existing 3D starter. Record which steps require help. If students cannot do these with the proposed preparation, supply scheduled support or reduce scope before X1; do not silently add prerequisite hours.
- [ ] Local Qwen reviews the planning pack; unresolved cohort facts keep the launch-readiness gate open.

## Risks

Unreliable metadata; source duplicates; vector success without citation readiness; unknown prior knowledge.
