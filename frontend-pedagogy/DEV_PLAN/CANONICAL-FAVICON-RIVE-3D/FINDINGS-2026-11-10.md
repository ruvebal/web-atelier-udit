# Readiness findings · 2026-11-10

These are repository/tool observations, not promises about the future implementation.

## F1 · The current object is illustrative, not canonical

`main.as` draws 24 vertices for each of 13 instances. `prismatic-favicon.wgsl` supplies one triangular prism and a manually authored array of 13 centres. No current GPU vertex is derived from `fava-mark-static.svg`.

**Consequence:** keep the runtime proof, replace the geometry authority.

## F2 · The canonical SVG already supplies stable facet order and colour

The static source contains 13 paths in painter order, each with a theme palette fill and a common scale transform. Path commands include many line segments and some non-trivial contours; the compiler must normalize transforms before area measurement and triangulation.

**Consequence:** facet identity is source order plus a generated stable ID; it is never inferred from colour.

## F3 · True 3D requires tessellation

GPU triangles cannot consume SVG path commands directly. “Verbatim front view” therefore means: normalize the SVG geometry, flatten curves at a recorded tolerance when present, triangulate it deterministically, and prove the front projection against a canonical raster reference.

**Consequence:** the generated manifest records source checksum, tolerance, area, winding, triangles, boundary rings, depth, bounds, and colour for every facet.

## F4 · The installed CLI can verify interaction and GPU structure

The local Rive CLI exposes pointer/touch simulation, semantic capture, screenshots, pixel probes/comparison, data dumps, repeatable seeds, benchmarks, and GPU-manifest output. These are sufficient to make the cascade gates executable instead of relying on visual confidence.

**Consequence:** X2–X4 gates use captures and data dumps; X6 records benchmark and GPU manifest evidence.

## F5 · A merge story cannot be authored before a merge exists

The implementation branch has no future PR number, review thread, merge commit, or merge timestamp. Publishing synthetic examples as if they were repository history would contradict the lesson’s evidence standard.

**Consequence:** X5 publishes the method and a pending provenance slot. X8 is a second, post-merge documentation hook that imports only real GitHub metadata and links back to immutable commits.
