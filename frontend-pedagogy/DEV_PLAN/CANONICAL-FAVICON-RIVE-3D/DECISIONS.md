# Frozen decisions

| ID  | Decision                                                                                                                                                                                                                                                                                                                                                 | Reason                                                                                                                                                      |
| --- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D1  | `fava-mark-static.svg` is the sole geometry and base-colour authority.                                                                                                                                                                                                                                                                                   | Prevents the demo, fallback, and favicon from drifting.                                                                                                     |
| D2  | Generated geometry is committed; hand-edited generated buffers are forbidden.                                                                                                                                                                                                                                                                            | Makes review and rebuild deterministic.                                                                                                                     |
| D3  | Every supported source path receives a deterministic ordinal ID in source order; IDs and buffers are generated for dynamic count `N`. The favicon fixture currently expects `N = 13`.                                                                                                                                                                    | Preserves painter order and stable interaction identity without turning one asset’s count into an engine limit.                                             |
| D4  | Intrinsic depth is `minDepth + (maxDepth - minDepth) × sqrt(area / maxArea)`, with `0 ≤ minDepth ≤ maxDepth`. Area is measured after SVG transforms and curve flattening, in normalized viewBox units.                                                                                                                                                   | Makes the surface/depth relationship unambiguous and bounded.                                                                                               |
| D5  | Area and depth bounds are generated constants documented in the manifest.                                                                                                                                                                                                                                                                                | No unexplained shader magic numbers.                                                                                                                        |
| D6  | Front and back faces plus boundary side walls are generated; back-face viewing must not reveal missing geometry.                                                                                                                                                                                                                                         | Enables a credible 360° inspection.                                                                                                                         |
| D7  | Rest pose is frontal, assembled, and raster-comparable to the canonical SVG.                                                                                                                                                                                                                                                                             | Keeps “same artwork, different spatial model” testable.                                                                                                     |
| D8  | Selection uses raw pointer coordinates and depth-aware picking; camera smoothing never changes hit identity.                                                                                                                                                                                                                                             | Keeps stylus input accurate without visual jitter.                                                                                                          |
| D9  | Click/tap toggles persistent selection; selected facets get a bounded Z offset and palette-state change.                                                                                                                                                                                                                                                 | Makes interaction legible and interruptible.                                                                                                                |
| D10 | Keyboard and screen-reader equivalents live in semantic HTML/Rive semantics; GPU pixels are never treated as accessible DOM.                                                                                                                                                                                                                             | Preserves the web contract.                                                                                                                                 |
| D11 | Reduced motion disables the automatic build/orbit loop while retaining deliberate facet inspection.                                                                                                                                                                                                                                                      | Motion preference does not remove content or interaction.                                                                                                   |
| D12 | Web integration uses a static canonical SVG/WebP fallback and preserves the existing theme.                                                                                                                                                                                                                                                              | Failure and unsupported GPU paths remain designed states.                                                                                                   |
| D13 | Rive MCP may assist editor composition if available, but the committed CLI/source pipeline remains authoritative.                                                                                                                                                                                                                                        | Keeps the build reproducible and portable beyond one editor session.                                                                                        |
| D14 | Public provenance is generated only from real Git/GitHub events.                                                                                                                                                                                                                                                                                         | No fabricated agentic theatre.                                                                                                                              |
| D15 | The merge-complete provenance update is a post-hook/docs PR after the implementation PR merges.                                                                                                                                                                                                                                                          | A PR cannot truthfully contain its own future merge commit.                                                                                                 |
| D16 | The extruder is a reusable SVG-path-to-mesh build tool; the favicon is its golden fixture, not embedded business logic.                                                                                                                                                                                                                                  | Other SVG identities must be able to reuse the verified geometry pipeline.                                                                                  |
| D17 | Reusability requires a second fixture containing a concave contour and a cubic curve.                                                                                                                                                                                                                                                                    | An abstraction tested only with the favicon is still favicon-specific.                                                                                      |
| D18 | Skill promotion happens only after a successful implementation iteration and independent cold review.                                                                                                                                                                                                                                                    | The studio skill should encode observed invariants, not speculative API design.                                                                             |
| D19 | Picking unprojects raw canvas coordinates through the exact current projection/view/model transforms, intersects the current animated triangles, rejects culled/negative hits, and returns the nearest positive visible facet.                                                                                                                           | Makes selection agree with GPU depth during separation, rotation, and selected Z offsets.                                                                   |
| D20 | The compiler publishes a versioned supported-subset schema. V1 accepts filled closed `M/L/C/Z` contours plus affine transforms; it rejects strokes, masks, filters, self-intersections, and multiple subpaths/holes with diagnostics.                                                                                                                    | “Reusable” must name its domain rather than imply universal SVG support.                                                                                    |
| D21 | The public lesson follows the graphics pipeline as separate ownership layers: vector representation → tessellation/mesh → model/view/projection transforms → visibility/depth → shading/rasterization → input/picking → time/interpolation → web semantics/fallback.                                                                                     | Local graphics sources support teaching architecture rather than a vendor-feature tour.                                                                     |
| D22 | Animation advances from elapsed time, not frame count; position and orientation interpolation are named separately.                                                                                                                                                                                                                                      | Frame-rate independence and quaternion/rotation interpolation are different technical problems.                                                             |
| D23 | Runtime choice is taught as an architectural trade-off: direct SVG DOM targets buy semantic/path interaction; Canvas/GPU pipelines buy centralized pixel/mesh control but require explicit picking and semantic twins.                                                                                                                                   | Preserves the renderer/interactivity boundary found in the SVG monograph evidence.                                                                          |
| D24 | The lesson exposes GPU setup cost separately from graphics ideas and measures shader bandwidth/computation rather than calling GPU rendering automatically efficient.                                                                                                                                                                                    | Current graphics pedagogy warns that modern API boilerplate can obscure the portable shader/pipeline concepts.                                              |
| D25 | Facet count is manifest data, never a shader/host/skill constant. Rendering, picking, animation staggering, semantic controls, reset state and tests iterate dynamic `N`; fixture-specific expected counts live only in golden tests.                                                                                                                    | The reusable skill must accept compositions with as many supported facets as their source requires.                                                         |
| D26 | The manifest declares all coordinate conventions: SVG-down-Y source space, normalized model space, camera handedness/forward axis, clip/depth convention, front winding and matrix multiplication order.                                                                                                                                                 | Projection, normals, culling and picking must share one explicit transform contract.                                                                        |
| D27 | Cubic paths are evaluated with the Bernstein form; adaptive flattening uses de Casteljau subdivision and a declared maximum projected-error tolerance. The tolerance rule is an engineering contract validated against dense samples, not misrepresented as a locally sourced theorem.                                                                   | “Verbatim” needs a measurable approximation boundary.                                                                                                       |
| D28 | Winding/area and normals are tested from signed cross products. General polygon area/centroid may use shoelace or triangulated area weighting, but is labelled as a derivation beyond the retained monograph’s triangle case.                                                                                                                            | Keeps sourced mathematics distinct from implementation generalization.                                                                                      |
| D29 | Camera state uses world → view/camera → projection order. Application Z, projected clip Z and depth-buffer encoding are separate named values and tests.                                                                                                                                                                                                 | Prevents a perspective formula from being mistaken for a GPU depth mapping.                                                                                 |
| D30 | Motion is elapsed-time based. Translation may use scalar/vector interpolation; orientation uses normalized quaternion interpolation where free rotation is required; pointer damping uses the exact exponential step `α = 1 - exp(-λΔt)` as an engineering inference tested across frame rates.                                                          | Makes motion portable across 30/60/144 Hz without conflating position and orientation.                                                                      |
| D31 | The lesson critiques motion on two axes: authored timeline principles (timing, anticipation, staging, follow-through, slow-in/out) and input-driven state quality (latency, interruption, persistence, reset, semantic reach).                                                                                                                           | Elegance is more than library syntax, and timeline craft is not the same problem as interaction architecture.                                               |
| D32 | Rive/AnimaScript 3D and SVG ingestion are separate, composable capabilities. `rive-animascript-3d` owns general mathematical/procedural geometry, authored meshes, scene animation, interaction and GPU/runtime portability; it has no SVG dependency. `svg-to-rive-3d` validates and compiles the supported SVG subset into the general scene contract. | Not every 3D animation begins as SVG; the backend must remain useful for parametric geometry, mathematical surfaces and other mesh sources.                 |
| D33 | Both skills begin as experimental contracts during X1–X6. X7 promotes only behavior proven by implementation evidence and independent review.                                                                                                                                                                                                            | Makes the reusable boundary available early without presenting speculative interfaces as stable studio knowledge.                                           |
| D34 | SVG compiler V1 uses a deliberately bounded XML/path grammar: no DTD/entities; one closed filled `M/L/C/Z` contour per path; absolute/relative commands and implicit coordinate repetition; path-local affine transforms composed in source order.                                                                                                       | Determinism and actionable rejection are safer than pretending a regular subset is a universal SVG parser.                                                  |
| D35 | The generated provider schema is `rive-animascript-3d/generated-provider/v1`: centered max-viewBox model units, right-handed coordinates, CCW fronts at Z=0, negative-Z backs, triangle-list positions/unit normals/indices, and manifest-owned dynamic facet spans.                                                                                     | Freezes the adapter/backend boundary before Rive scene implementation.                                                                                      |
| D36 | Compiler V1 paint is deliberately opaque and resolved: 3/6-digit hex or bounded comma-form `rgb()`, inline `fill`/`fill-rule`/`stroke:none` only, and no class, opacity, alpha-bearing fill, inheritance, variables, paint functions, or unknown presentation attributes.                                                                                | The copied SVG fallback and generated material record must not diverge through CSS or paint semantics the provider cannot encode.                           |
| D37 | The bounded XML start-tag lexer must fully consume its input: unique names, explicit `=`, quoted values, no malformed residue, and namespaces only where the root allowlist declares them.                                                                                                                                                               | A semantic allowlist is meaningless if malformed tokens can disappear before validation.                                                                    |
| D38 | Compiler V1 document shape is one root `svg`, direct self-closing `path` children only, and exact `</svg>` closure. Tag scanning is quote-aware, comments are ignored only outside tags, and nested/multiple SVG viewports, containers, explicit path closures, malformed delimiters, slash residue, and markup inside attribute values are rejected.    | Every admitted coordinate/style context must be baked; the flat V1 adapter must not silently ignore nested viewport semantics or malformed lexical residue. |
| D39 | A path `Z`/`z` closepath terminates the single V1 contour; any later drawing command, including SVG's implicit post-close subpath, rejects. Transform attributes use a strict tokenizer with named functions, exact numeric arity, no empty arguments, and legal separators. Root `xmlns`/`xmlns:xlink` must be the SVG/XLink namespaces when present, and `width`/`height` are optional positive unitless-or-`px` lengths rather than geometry inputs. | Post-close commands and malformed transform lists are source/fallback divergence risks; constraining root metadata keeps the bounded document honest without widening the geometry contract. |
| D40 | Compiler V1 whitespace is XML `S` only (`U+0020`, `U+0009`, `U+000D`, `U+000A`); JavaScript `\s`/Unicode `trim` classes are never grammar separators. Path coordinates, transform arguments, normalized rings, signed area, centroid, depth, and emitted position/normal buffers must all be finite or compilation fails. | Non-XML whitespace (NBSP, U+2028, FEFF, FF/VT) and non-finite/overflowing coordinates otherwise normalize into geometry the copied fallback cannot reproduce or serialize as `null` provider data. |
| D41 | `viewBox` tokens must match the SVG number grammar (sign, decimal, exponent — never `Number()` coercion such as `0x`/`0b`/`0o`) and be separated by single comma-wsp boundaries; path commas may appear only between two numbers; XML comments must be well-formed (no `--` inside, no trailing `-`); attribute values and comment bodies may contain only XML characters. | `Number()` coercion, collapsed comma runs, malformed comments, and non-XML characters silently reinterpret or invalidate source that `fallback.svg` preserves verbatim. |
| D42 | Attribute maps use null-prototype objects so names like `__proto__` reach the allowlists instead of being silently dropped, and an optional XML declaration must match the strict `XMLDecl` production (version first, optional encoding, optional standalone) containing only XML characters. | Silent prototype-key drops and unvalidated prologs are the same trust-boundary escape class as unquoted attributes: source the compiler ignores but `fallback.svg` preserves. |
