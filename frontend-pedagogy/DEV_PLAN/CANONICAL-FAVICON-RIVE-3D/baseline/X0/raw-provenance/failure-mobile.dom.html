One mark.
Seven motion engines.

Round 1 holds the result constant: the same ruvebal favicon artwork and the same staggered reveal. Round 2 changes the motion task so each technique can show its strongest fit. Round 3 compares facet-level interaction, state, and interruption. Round 4 separates a flat SVG, a CSS-composited plane, mathematical 2.5D, and true mesh geometry. The tab favicon cycles through the course palette; the demo uses a separate static copy so it cannot bias the comparison.

Code convention: every Key code disclosure is an Excerpt of the mechanism beside it, not a standalone file. Open the disclosure after using the specimen; links on exported assets lead to their complete source.

All techniques are ready; replay any version to compare.

Round 3: interaction lab

Round 4: spatial truth lab

The artwork stays recognisable while the spatial model changes. Compare what owns depth, which visual cues are simulated, and whether the original SVG remains an accessible DOM document.

Flat SVG source

2D vector

Scalable paths, crisp colour, and direct DOM semantics when inline. There is no Z axis, camera, light, or occlusion.

Best economy: identity, icons, and direct facet interaction
Key code

Excerpt · key mechanism

<svg viewBox="0 0 1024 920" role="img">
  <path class="facet" d="…" fill="var(--facet-1)" />
</svg>

CSS perspective

Planar 3D

The browser composites the complete SVG in perspective. The plane can rotate and translate in Z, but its facets gain no thickness.

Best economy: cards, covers, and whole-mark tilts
Key code

Excerpt · key mechanism

.scene { perspective: 800px; }
.plane {
  transform-style: preserve-3d;
  transform: rotateX(var(--pitch)) rotateY(var(--yaw));
}

Canvas projection

2.5D math

Projected 2.5D: pointer position changes the virtual camera; painter order replaces a depth buffer.

Every unchanged SVG path receives a fixed Z value, but its initial depth contribution is zero so the first frame is the exact frontal 2D composition. Pointer entry eases depth on: yaw shifts facets horizontally, pitch shifts them vertically, and perspective scales them by FOV / (FOV − depth); facets are then painted back to front. This is a projected flat image, not buoyancy or a mesh with a depth buffer.

Best economy: many lightweight shapes with camera-like response
Key code

Excerpt · key mechanism

const perspective = fov / (fov - projectedDepth);
context.setTransform(scale * perspective, 0, 0, scale * perspective, x, y);
facets.sort((a, b) => a.depth - b.depth)
  .forEach(({ path }) => context.fill(path));

Three.js extrusion

True 3D

True 3D: extruded meshes, perspective camera, lights, materials, and depth testing.

SVGLoader translates paths into shapes; extrusion creates geometry with thickness. A camera, materials, lights, and depth buffer now own the result. Use Orbit 360° to inspect the actual front, side, and back surfaces—not a 2.5D approximation.

Best capability: geometry, lighting, occlusion, and spatial cameras
Key code

Excerpt · key mechanism

const shapes = SVGLoader.createShapes(path);
const geometry = new THREE.ExtrudeGeometry(shapes[0], {
  depth: 18,
  bevelEnabled: true
});
scene.add(new THREE.Mesh(geometry, material));
Do not infer 3D from the graphics API.

dotLottie can use WebGL2 or WebGPU and still render a two-dimensional timeline. GSAP, Motion, and Anime.js can animate Three.js values but do not render the scene. Current Rive can combine vectors and native 3D in one scene, and AnimaScript can drive its procedural logic. That capability does not make every Rive file three-dimensional: the timeline .riv and path-drawn scripted favicon remain 2D, while the new prismatic GPU Canvas specimen is true 3D because it supplies geometry, perspective, lighting, and a depth buffer. The Canvas projection specimen above is projected 2.5D: it gives flat SVG facets synthetic Z values, perspective scale, and painter order, but has no meshes, thickness, lights, or depth buffer.

Contest verdict

Best economy for this reveal

CSS keyframes or transitions: no dependency, direct ownership, and enough control for a short one-shot sequence.

Best course fit for richer choreography

GSAP: the course already teaches it, and its timeline is easy to explain, inspect, interrupt, and extend.

Best for interaction as authored logic

Rive wins when states, transitions, listeners, and data binding must travel with the asset. Lottie wins at timeline control, not per-facet DOM interaction.
